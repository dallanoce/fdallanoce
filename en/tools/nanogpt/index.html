Before we start

The map

nanoGPT is GPT-2 written in three hundred lines. This page runs a tiny copy of it — same code, same operations, dimensions shrunk until every matrix can be printed with its numbers — and follows it from the first character to the last probability.

This page's model

On load the weights are nanoGPT's initialisation: small random numbers, a model that knows nothing yet. You can read the page like that and see what a GPT looks like at step zero, or train it now: it takes about twenty seconds, and from then on every lab shows the learned weights.

Part one

From characters to vectors

A language model does not see letters: it sees integers, and then vectors. Three steps take the text to the matrix x that enters the first Block, and none of them is mysterious.

The vocabulary: encode and decode

The character-level version of nanoGPT uses no tokenizer: it takes the distinct characters of the text, sorts them, and a character's number is its position in that list. On Tiny Shakespeare there are 65 — newline, space, eleven punctuation marks, the capitals and the lowercase letters.

get_batch: one window is eight examples

Training picks batch_size random windows of length block_size. The target y is the same window shifted by one character: for each position, the character that comes next. A window of 8 therefore holds 8 examples, with contexts from 1 to 8 characters long, which is why the model also learns to start from a very short context.

tok_emb + pos_emb: the first x

wte is a table with one row per character in the vocabulary, wpe one with a row per position. A token's embedding is just a row read from the table: the sum of the two rows is the vector that stands for "this character in this position". Dropout is off here, so drop lets everything through.

An embedding is a matrix product Why the table can be trained like any linear layer.

Reading row i of Wte is the same as multiplying Wte by a vector of length V that is all zeros except for a 1 at position i, a "one-hot". nn.Embedding skips the multiplication, which would be almost entirely by zero, but the gradient is the product's: it only reaches the rows of the characters the batch actually contains.

Part two

The Block

All the model's work happens here, repeated n_layer times. A Block does two things in a row: attention, where each position gathers information from the earlier ones, and the MLP, where each position processes it on its own. Karpathy puts it this way: communication, then computation.

The residual stream

The two lines of Block.forward do not replace x: they add something to it. Each position's vector is a tape that runs through the whole model, and every sub-block reads the tape and writes a correction onto it. 

class Block(nn.Module):     def __init__(self, config):        super().__init__()        self.ln_1 = LayerNorm(config.n_embd, bias=config.bias)        self.attn = CausalSelfAttention(config)        self.ln_2 = LayerNorm(config.n_embd, bias=config.bias)        self.mlp = MLP(config)     def forward(self, x):        x = x + self.attn(self.ln_1(x))        x = x + self.mlp(self.ln_2(x))        return x

The sum lets the gradient through

The derivative of x + f(x) with respect to x contains a 1. Going backwards the signal reaches the first Block intact even when f damps it: that is what makes it possible to stack dozens of layers.

Pre-norm

The LayerNorm sits inside the branch, before attn and mlp, not after the sum as in the 2017 Transformer. The tape itself is never normalised: that is why ln_f is needed at the end.

c_proj starts smaller

The two layers that write onto the tape, attn.c_proj and mlp.c_proj, start with standard deviation 0.02 / √(2 · n_layer): there are 2 · n_layer additions, and without the correction the variance of the tape would grow with depth.

LayerNorm

Row by row, that is token by token: subtract the mean of the C numbers, divide by their standard deviation, then multiply by weight and add bias, two learned vectors. nanoGPT rewrites the class only to be able to drop the bias, which PyTorch did not let you switch off back then. 

class LayerNorm(nn.Module):    """ LayerNorm but with an optional bias. PyTorch doesn't support simply bias=False """     def __init__(self, ndim, bias):        super().__init__()        self.weight = nn.Parameter(torch.ones(ndim))        self.bias = nn.Parameter(torch.zeros(ndim)) if bias else None     def forward(self, input):        return F.layer_norm(input, self.weight.shape, self.weight, self.bias, 1e-5)

The variance is the "population" one, divided by C and not by C − 1, as in F.layer_norm. ε is not decoration: when the incoming numbers are small, as at step zero, it weighs on the division and the output comes out with variance visibly below 1.

CausalSelfAttention, step by step

The heart of the Transformer. Each position produces three vectors: a query q ("what am I looking for"), a key k ("what do I contain") and a value v ("what I hand over to whoever picks me"). The product of queries and keys says how much each position should listen to each earlier one, and the answer is a weighted average of the values. Everything else is bookkeeping of shapes.

def forward(self, x):    B, T, C = x.size() # batch size, sequence length, embedding dimensionality (n_embd)     # calculate query, key, values for all heads in batch and move head forward to be the batch dim    q, k, v  = self.c_attn(x).split(self.n_embd, dim=2)    k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)    q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)    v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)     # causal self-attention; Self-attend: (B, nh, T, hs) x (B, nh, hs, T) -> (B, nh, T, T)    if self.flash:        # efficient attention using Flash Attention CUDA kernels        y = torch.nn.functional.scaled_dot_product_attention(q, k, v, attn_mask=None, dropout_p=self.dropout if self.training else 0, is_causal=True)    else:        # manual implementation of attention        att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))        att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))        att = F.softmax(att, dim=-1)        att = self.attn_dropout(att)        y = att @ v # (B, nh, T, T) x (B, nh, T, hs) -> (B, nh, T, hs)    y = y.transpose(1, 2).contiguous().view(B, T, C) # re-assemble all head outputs side by side     # output projection    y = self.resid_dropout(self.c_proj(y))    return y

Step 1 of 10

c_attn: three projections in one

[ q | k | v ] = x W⊤ + b ,   W ∈ ℝ3C×C

A single linear layer takes each row of x from C = 16 to 3C = 48 numbers, and split(n_embd, dim=2) cuts them into three slices of 16: q, k and v. It is an optimisation: three separate matrices would give the same result with three multiplications instead of one. The weight is stored as (3C, C), like every nn.Linear, and the transpose is in the formula.

Step 2 of 10

view and transpose: the heads

(B, T, C) → view → (B, T, nh, hs) → transpose(1, 2) → (B, nh, T, hs)

No number changes: the C columns of q are read as nh = 2 groups of hs = 8, and each group becomes a head of its own. After the transpose the head dimension sits next to the batch one, and from here on each head works as if it were an independent attention, in parallel with the others. Below, the colour of the bands says which column goes to which head.

Step 3 of 10

q @ kᵀ: how alike query and key are

attij = qi · kj = Σd qid kjd

Every query against every key: one T × T matrix per head. Row i says how interested position i is in each position j. Click a cell to see its dot product written out in full.

Step 4 of 10

The 1/√hs scale

att ← att · 1√hs ,   k.size(-1) = hs = 8

A dot product of hs random terms has standard deviation √hs: the wider the heads, the larger the scores, and a softmax of large numbers becomes almost a one-hot that looks at a single position and has an almost zero gradient. Dividing by √hs brings the scores back to unit variance, whatever hs is. The panel below the lab shows it.

Step 5 of 10

The causal mask

attij ← −∞  if  biasij = 0 ,  that is if j > i

self.bias is not a bias: it is the triangular matrix torch.tril(torch.ones(T, T)), registered as a buffer. Everything above the diagonal — the future positions — becomes −∞. Without the mask, during training the model would read the answer: the character to predict is right there, one column to the right.

Step 6 of 10

softmax, row by row

attij ← eattijΣk ≤ i eattik ,   e−∞ = 0

Each row becomes a probability distribution: positive numbers that add up to 1, as the column on the right checks. The −∞ cells come out at exactly zero. At step zero the rows are nearly uniform — 1, then ½ ½, then ⅓ ⅓ ⅓ — because queries and keys are still small noise: a model that knows nothing listens to everyone equally.

Step 7 of 10

attn_dropout

att ← att ⊙ m / (1 − p) ,   mij ∼ Bernoulli(1 − p)

During training dropout zeroes a random fraction p of the attention weights and multiplies the rest by 1/(1 − p), so the average stays the same. Here dropout = 0.0 and the step does nothing, as in evaluation. Pick p = 0.2 to see what it would do in training: the rows stop adding up to 1.

Step 8 of 10

att @ v: the weighted average of the values

yi = Σj ≤ i attij vj

Each row of att is a recipe: how much to take of each value. The head's output for position i is the blend of the v vectors of positions 0 to i. It is the only place in the model where information moves from one position to another. Click a cell of y to see the blend.

Step 9 of 10

The heads go back side by side

y = [ y(0) | y(1) ] ,   (B, nh, T, hs) → (B, T, C)

The opposite of step 2: transpose puts the heads back next to the positions and view glues the nh outputs of hs numbers into a single vector of C. contiguous() is needed because after the transpose the numbers are no longer in order in memory, and view insists that they are.

Step 10 of 10

c_proj, then the residual add

out = y Wproj⊤ + b ,   x ← x + out

The heads have worked separately; c_proj, a C × C matrix, mixes their outputs and decides what to write onto the tape. The result does not replace x: it is added to it, in the first line of Block.forward. resid_dropout, like the other one, is off here.

The flash branch Lines 62–64: the same maths, a different memory strategy.

With PyTorch 2 nanoGPT calls scaled_dot_product_attention(q, k, v, is_causal=True), which computes exactly steps 3–8 in a single kernel. The difference is that it never builds the whole att matrix: it walks through it in blocks, keeping a "running" softmax. Memory goes from T² to T per head, which is why the manual branch above is the one you read, but almost never the one that runs.

All the heads together

The att matrix of every head of every Block, for the same prompt. At step zero they are all the same, the grey scale of ignorance. After training each head specialises: one looks at the character just before, another at the start of the word, another spreads out — not because anyone told it to, but because it helped predict the next character.

MLP: widen, bend, narrow

The second sub-block does not look at other positions: it works on each vector on its own. It takes it from C to 4·C = 64 dimensions, applies a non-linearity, and brings it back to C. Almost half of each Block's parameters live here. 

class MLP(nn.Module):     def __init__(self, config):        super().__init__()        self.c_fc    = nn.Linear(config.n_embd, 4 * config.n_embd, bias=config.bias)        self.gelu    = nn.GELU()        self.c_proj  = nn.Linear(4 * config.n_embd, config.n_embd, bias=config.bias)        self.dropout = nn.Dropout(config.dropout)     def forward(self, x):        x = self.c_fc(x)        x = self.gelu(x)        x = self.c_proj(x)        x = self.dropout(x)        return x

Part three

From the last vector to the loss

After the last Block, each position has a vector of C numbers. Two steps remain to turn it into a prediction — and one to measure how wrong it was.

ln_f, lm_head and the tied weights

ln_f normalises the tape, which is never normalised inside the Blocks. Then lm_head, a Linear from C to V without bias, gives each character a score: the logits. Line 138 is the detail not to miss: lm_head's weight is wte. Not a copy: the same tensor. The table that turns a character into a vector at the input measures, at the output, how much a vector resembles each character.

Almost a quarter fewer parameters

In gpt2, wte is 50,257 × 768: 38.6 million numbers. Without tying, lm_head would add as many again, and the model would go from 124 to 163 million. Here it is 1,040 out of 7,760.

At inference, only the last position

Without targets, nanoGPT applies lm_head only to x[:, [-1], :]: choosing the next character needs only the last prediction. The list [-1] instead of -1 keeps the T dimension, which stays of length 1.

logits and cross_entropy

Each row of logits goes through a softmax and becomes a distribution over the 65 characters. The loss looks only at the probability given to the right character, takes its negative log, and averages over the positions. A model that guesses gives 1/65 to everything: −ln(1/65) = 4.17 is the loss every training run starts from.

Part four

Training

Training means repeating the same thing thousands of times: a batch, the loss, the gradient of every weight, a small step in the direction that lowers the loss. In train.py the core is about twenty lines; the rest is GPU bookkeeping.

get_lr: warmup and cosine

The learning rate is not constant. It climbs in a straight line for warmup_iters steps, because early gradients are large and Adam's estimates are still empty; then it goes down half a cosine to min_lr, which it reaches at lr_decay_iters and keeps from then on. 

def get_lr(it):    # 1) linear warmup for warmup_iters steps    if it < warmup_iters:        return learning_rate * (it + 1) / (warmup_iters + 1)    # 2) if it > lr_decay_iters, return min learning rate    if it > lr_decay_iters:        return min_lr    # 3) in between, use cosine decay down to min learning rate    decay_ratio = (it - warmup_iters) / (lr_decay_iters - warmup_iters)    assert 0 <= decay_ratio <= 1    coeff = 0.5 * (1.0 + math.cos(math.pi * decay_ratio)) # coeff ranges 0..1    return min_lr + coeff * (learning_rate - min_lr)

AdamW, and the two parameter groups

configure_optimizers splits the parameters by their number of dimensions: matrices — Linear weights and embeddings — get weight decay, vectors — biases and LayerNorms — do not. Shrinking a weight matrix towards zero regularises; shrinking a bias or a LayerNorm's gain would only move the operating point.

The "W" in AdamW stands for decoupled weight decay: the weight is shrunk directly, before the step, instead of adding λθ to the gradient as Adam with L2 regularisation did — where the decay ended up divided by √v̂ along with everything else. lm_head.weight does not appear: named_parameters() does not repeat a shared tensor.

Gradient accumulation and clipping

gradient_accumulation_steps

A batch that does not fit in memory is split into micro-batches: the gradient accumulates over all of them before the optimiser step. The loss is divided by their number, so the sum of the gradients is the average the whole batch would have given. Here it is 1.

clip_grad_norm_

If the norm of all the gradients taken together exceeds grad_clip = 1, they are all scaled by the same factor: g ← g · min(1, c / ‖g‖). The direction stays the same, only the length of the step changes. It is the seat belt against an unlucky batch.

Part five

Sampling

A GPT writes one character at a time: it computes the distribution of the next one, draws one, appends it and starts again. The model has no memory between rounds: it rereads the whole context every time, up to block_size characters.

generate()

Two knobs change the character drawn without touching the model. temperature divides the logits before the softmax: below 1 the distribution tightens around the favourite, above 1 it flattens. top_k keeps only the k best candidates and sends the others to −∞. 

def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):    """    Take a conditioning sequence of indices idx (LongTensor of shape (b,t)) and complete    the sequence max_new_tokens times, feeding the predictions back into the model each time.    Most likely you'll want to make sure to be in model.eval() mode of operation for this.    """    for _ in range(max_new_tokens):        # if the sequence context is growing too long we must crop it at block_size        idx_cond = idx if idx.size(1) <= self.config.block_size else idx[:, -self.config.block_size:]        # forward the model to get the logits for the index in the sequence        logits, _ = self(idx_cond)        # pluck the logits at the final step and scale by desired temperature        logits = logits[:, -1, :] / temperature        # optionally crop the logits to only the top k options        if top_k is not None:            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))            logits[logits < v[:, [-1]]] = -float('Inf')        # apply softmax to convert logits to (normalized) probabilities        probs = F.softmax(logits, dim=-1)        # sample from the distribution        idx_next = torch.multinomial(probs, num_samples=1)        # append sampled index to the running sequence and continue        idx = torch.cat((idx, idx_next), dim=1)     return idx
