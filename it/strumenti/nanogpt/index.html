Parte prima

Dai caratteri ai vettori

Un modello linguistico non vede lettere: vede interi, e poi vettori. Tre passaggi portano dal testo alla matrice x che entra nel primo Block, e nessuno dei tre ha niente di misterioso.

Il vocabolario: encode e decode

La versione a caratteri di nanoGPT non usa un tokenizer: prende i caratteri distinti del testo, li mette in ordine, e il numero di un carattere è la sua posizione in quella lista. Su Tiny Shakespeare sono 65 — l'a capo, lo spazio, undici segni, le maiuscole e le minuscole.

tok_emb + pos_emb: il primo x

wte è una tabella con una riga per carattere del vocabolario, wpe una con una riga per posizione. L'embedding di un token è solo una riga letta dalla tabella: la somma delle due righe è il vettore che rappresenta "questo carattere in questa posizione". Il dropout qui è spento, quindi drop lascia passare tutto. 

def forward(self, idx, targets=None):    device = idx.device    b, t = idx.size()    assert t <= self.config.block_size, f"Cannot forward sequence of length {t}, block size is only {self.config.block_size}"    pos = torch.arange(0, t, dtype=torch.long, device=device) # shape (t)     # forward the GPT model itself    tok_emb = self.transformer.wte(idx) # token embeddings of shape (b, t, n_embd)    pos_emb = self.transformer.wpe(pos) # position embeddings of shape (t, n_embd)    x = self.transformer.drop(tok_emb + pos_emb)    for block in self.transformer.h:        x = block(x)    x = self.transformer.ln_f(x)     if targets is not None:        # if we are given some desired targets also calculate the loss        logits = self.lm_head(x)        loss = F.cross_entropy(logits.view(-1, logits.size(-1)), targets.view(-1), ignore_index=-1)    else:        # inference-time mini-optimization: only forward the lm_head on the very last position        logits = self.lm_head(x[:, [-1], :]) # note: using list [-1] to preserve the time dim        loss = None     return logits, loss

Posizione

In alto le tre matrici intere, solo colore; sotto, la posizione scelta con i suoi numeri. Il colore di ogni matrice è scalato sul suo valore più grande in modulo: verde positivo, rosso negativo. Al passo zero i numeri sono piccoli (deviazione 0,02): è l'inizializzazione di nanoGPT, non un errore.
Un embedding è un prodotto per una matrice Perché la tabella si può allenare come un qualunque strato lineare.

Leggere la riga i di Wte è la stessa cosa che moltiplicare per Wte un vettore lungo V tutto a zero tranne un 1 in posizione i, un "one-hot". nn.Embedding salta la moltiplicazione, che sarebbe quasi tutta per zero, ma il gradiente è quello del prodotto: arriva solo alle righe dei caratteri che il batch contiene davvero.

Parte seconda

Il Block

Tutto il lavoro del modello avviene qui, ripetuto n_layer volte. Un Block fa due cose in fila: l'attenzione, dove ogni posizione raccoglie informazione dalle precedenti, e l'MLP, dove ogni posizione la elabora per conto suo. Karpathy lo riassume così: prima comunicare, poi calcolare.

Il flusso residuo

Le due righe di Block.forward non sostituiscono x: gli aggiungono qualcosa. Il vettore di ogni posizione è un nastro che attraversa tutto il modello, e ogni sotto-blocco legge il nastro e ci scrive sopra una correzione. 

class Block(nn.Module):     def __init__(self, config):        super().__init__()        self.ln_1 = LayerNorm(config.n_embd, bias=config.bias)        self.attn = CausalSelfAttention(config)        self.ln_2 = LayerNorm(config.n_embd, bias=config.bias)        self.mlp = MLP(config)     def forward(self, x):        x = x + self.attn(self.ln_1(x))        x = x + self.mlp(self.ln_2(x))        return x

La somma fa passare il gradiente

La derivata di x + f(x) rispetto a x contiene un 1. All'indietro il segnale arriva intatto al primo Block anche quando f lo attenua: è quello che permette di impilare decine di strati.

Pre-norm

La LayerNorm sta dentro il ramo, prima di attn e mlp, non dopo la somma come nel Transformer del 2017. Il nastro non viene mai normalizzato: per questo serve ln_f alla fine.

c_proj nasce più piccolo

I due strati che scrivono sul nastro, attn.c_proj e mlp.c_proj, partono con deviazione 0,02 / √(2 · n_layer): sono 2 · n_layer somme, e senza la correzione la varianza del nastro crescerebbe con la profondità.

LayerNorm

Riga per riga, cioè token per token: si toglie la media dei C numeri, si divide per la loro deviazione standard, poi si moltiplica per weight e si somma bias, due vettori imparati. nanoGPT riscrive la classe solo per poter togliere il bias, che PyTorch allora non permetteva di spegnere. 

class LayerNorm(nn.Module):    """ LayerNorm but with an optional bias. PyTorch doesn't support simply bias=False """     def __init__(self, ndim, bias):        super().__init__()        self.weight = nn.Parameter(torch.ones(ndim))        self.bias = nn.Parameter(torch.zeros(ndim)) if bias else None     def forward(self, input):        return F.layer_norm(input, self.weight.shape, self.weight, self.bias, 1e-5)

Posizione

Sopra l'ingresso, sotto l'uscita: i C = 16 numeri di una posizione, ognuno con la sua scala.

La varianza è quella "di popolazione", divisa per C e non per C − 1, come in F.layer_norm. ε non è decorativo: quando i numeri in ingresso sono piccoli, come al passo zero, pesa sulla divisione e l'uscita esce con varianza visibilmente sotto 1.

CausalSelfAttention, passo per passo

Il cuore del Transformer. Ogni posizione produce tre vettori: una domanda q ("che cosa sto cercando"), una chiave k ("che cosa contengo") e un valore v ("che cosa passo a chi mi sceglie"). Il prodotto fra domande e chiavi dice quanto ogni posizione deve ascoltare ciascuna delle precedenti, e la risposta è una media pesata dei valori. Tutto il resto è contabilità delle forme.

Attention(Q, K, V) = softmax( Q K⊤ √hs + M ) V ,   Mij = 0 se j ≤ i, −∞ altrimenti

def forward(self, x):    B, T, C = x.size() # batch size, sequence length, embedding dimensionality (n_embd)     # calculate query, key, values for all heads in batch and move head forward to be the batch dim    q, k, v  = self.c_attn(x).split(self.n_embd, dim=2)    k = k.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)    q = q.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)    v = v.view(B, T, self.n_head, C // self.n_head).transpose(1, 2) # (B, nh, T, hs)     # causal self-attention; Self-attend: (B, nh, T, hs) x (B, nh, hs, T) -> (B, nh, T, T)    if self.flash:        # efficient attention using Flash Attention CUDA kernels        y = torch.nn.functional.scaled_dot_product_attention(q, k, v, attn_mask=None, dropout_p=self.dropout if self.training else 0, is_causal=True)    else:        # manual implementation of attention        att = (q @ k.transpose(-2, -1)) * (1.0 / math.sqrt(k.size(-1)))        att = att.masked_fill(self.bias[:,:,:T,:T] == 0, float('-inf'))        att = F.softmax(att, dim=-1)        att = self.attn_dropout(att)        y = att @ v # (B, nh, T, T) x (B, nh, T, hs) -> (B, nh, T, hs)    y = y.transpose(1, 2).contiguous().view(B, T, C) # re-assemble all head outputs side by side     # output projection    y = self.resid_dropout(self.c_proj(y))    return y

Passo 4 di 10

La scala 1/√hs

att ← att · 1√hs ,   k.size(-1) = hs = 8

Un prodotto scalare di hs termini casuali ha deviazione standard √hs: più larghe le teste, più grandi i punteggi, e una softmax di numeri grandi diventa quasi un one-hot che guarda una posizione sola e ha gradiente quasi nullo. Dividere per √hs riporta i punteggi a varianza 1, qualunque sia hs. Il riquadro sotto il laboratorio lo fa vedere.

Ogni riga diventa una distribuzione di probabilità: numeri positivi che sommano a 1, la colonna a destra lo verifica. Le celle a −∞ escono esattamente a zero. Il ramo flash Righe 62–64: stessa matematica, un'altra strategia di memoria.

Con PyTorch 2 nanoGPT chiama scaled_dot_product_attention(q, k, v, is_causal=True), che calcola esattamente i passi 3–8 in un solo kernel. La differenza è che non costruisce mai la matrice att intera: la percorre a blocchi, tenendo una softmax "in corsa". La memoria passa da T² a T per testa, ed è il motivo per cui il ramo manuale qui sopra è quello che si legge, ma quasi mai quello che si esegue.

Tutte le teste insieme

La matrice att di ogni testa di ogni Block, per lo stesso prompt. Al passo zero sono tutte uguali, la scala di grigi dell'ignoranza. Dopo l'addestramento ogni testa si specializza: una guarda il carattere appena prima, un'altra l'inizio della parola, un'altra ancora si distribuisce — non perché qualcuno gliel'abbia detto, ma perché serviva a prevedere il carattere dopo.

MLP: allargare, piegare, restringere

Il secondo sotto-blocco non guarda le altre posizioni: lavora su ogni vettore da solo. Lo porta da C a 4·C = 64 dimensioni, ci applica una non linearità, e lo riporta a C. È qui che sta quasi metà dei parametri di ogni Block. 

class MLP(nn.Module):     def __init__(self, config):        super().__init__()        self.c_fc    = nn.Linear(config.n_embd, 4 * config.n_embd, bias=config.bias)        self.gelu    = nn.GELU()        self.c_proj  = nn.Linear(4 * config.n_embd, config.n_embd, bias=config.bias)        self.dropout = nn.Dropout(config.dropout)     def forward(self, x):        x = self.c_fc(x)        x = self.gelu(x)        x = self.c_proj(x)        x = self.dropout(x)        return x

In inferenza, solo l'ultima posizione

Senza targets, nanoGPT applica lm_head solo a x[:, [-1], :]: per scegliere il prossimo carattere serve solo l'ultima previsione. La lista [-1] invece di -1 tiene la dimensione T, che resta lunga 1.

logits e cross_entropy

Ogni riga di logits passa per una softmax e diventa una distribuzione sui 65 caratteri. La loss guarda solo la probabilità data al carattere giusto, ne prende il logaritmo cambiato di segno, e fa la media sulle posizioni. Un modello che tira a indovinare dà 1/65 a tutto: −ln(1/65) = 4,17 è la loss da cui parte ogni addestramento.

get_lr: riscaldamento e coseno

Il learning rate non è costante. Sale in linea retta per warmup_iters passi, perché all'inizio i gradienti sono grandi e le stime di Adam ancora vuote; poi scende lungo mezzo coseno fino a min_lr, che si raggiunge a lr_decay_iters e da lì resta fermo. 

def get_lr(it):    # 1) linear warmup for warmup_iters steps    if it < warmup_iters:        return learning_rate * (it + 1) / (warmup_iters + 1)    # 2) if it > lr_decay_iters, return min learning rate    if it > lr_decay_iters:        return min_lr    # 3) in between, use cosine decay down to min learning rate    decay_ratio = (it - warmup_iters) / (lr_decay_iters - warmup_iters)    assert 0 <= decay_ratio <= 1    coeff = 0.5 * (1.0 + math.cos(math.pi * decay_ratio)) # coeff ranges 0..1    return min_lr + coeff * (learning_rate - min_lr)

AdamW, e i due gruppi di parametri

configure_optimizers divide i parametri in base al numero di dimensioni: le matrici — pesi dei Linear ed embedding — ricevono il weight decay, i vettori — bias e LayerNorm — no. Restringere verso zero una matrice di pesi regolarizza; restringere un bias o il guadagno di una LayerNorm sposterebbe solo il punto di lavoro.

La "W" di AdamW sta per weight decay disaccoppiato: il peso viene rimpicciolito direttamente, prima del passo, invece di sommare λθ al gradiente come faceva Adam con la regolarizzazione L2 — dove il decay finiva diviso per √v̂ insieme a tutto il resto. lm_head.weight non compare: named_parameters() non ripete un tensore condiviso.

Accumulo e taglio del gradiente

gradient_accumulation_steps

Un batch che non sta in memoria si spezza in micro-batch: il gradiente si accumula su tutti prima del passo dell'ottimizzatore. La loss si divide per il loro numero, così la somma dei gradienti è la media che avrebbe dato il batch intero. Qui vale 1.

clip_grad_norm_

Se la norma di tutti i gradienti messi insieme supera grad_clip = 1, vengono scalati tutti dello stesso fattore: g ← g · min(1, c / ‖g‖). La direzione resta quella, cambia solo la lunghezza del passo. È la cintura di sicurezza contro un batch sfortunato.

Parte quinta

Generazione

Un GPT scrive un carattere alla volta: calcola la distribuzione del prossimo, ne estrae uno, lo aggiunge in fondo e ricomincia. Il modello non ha memoria fra un giro e l'altro: rilegge ogni volta tutto il contesto, fino a block_size caratteri.

generate()

Due manopole cambiano il carattere estratto senza toccare il modello. temperature divide i logits prima della softmax: sotto 1 la distribuzione si stringe sul favorito, sopra 1 si appiattisce. top_k tiene solo i k candidati migliori e manda gli altri a −∞. 

def generate(self, idx, max_new_tokens, temperature=1.0, top_k=None):    """    Take a conditioning sequence of indices idx (LongTensor of shape (b,t)) and complete    the sequence max_new_tokens times, feeding the predictions back into the model each time.    Most likely you'll want to make sure to be in model.eval() mode of operation for this.    """    for _ in range(max_new_tokens):        # if the sequence context is growing too long we must crop it at block_size        idx_cond = idx if idx.size(1) <= self.config.block_size else idx[:, -self.config.block_size:]        # forward the model to get the logits for the index in the sequence        logits, _ = self(idx_cond)        # pluck the logits at the final step and scale by desired temperature        logits = logits[:, -1, :] / temperature        # optionally crop the logits to only the top k options        if top_k is not None:            v, _ = torch.topk(logits, min(top_k, logits.size(-1)))            logits[logits < v[:, [-1]]] = -float('Inf')        # apply softmax to convert logits to (normalized) probabilities        probs = F.softmax(logits, dim=-1)        # sample from the distribution        idx_next = torch.multinomial(probs, num_samples=1)        # append sampled index to the running sequence and continue        idx = torch.cat((idx, idx_next), dim=1)     return idx
